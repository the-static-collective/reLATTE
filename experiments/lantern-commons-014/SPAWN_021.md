# SPAWN 021 — Learning Loom

## From infinite possibilities to tested, transmissible methods

SPAWN 017: one person can operate many hats.
SPAWN 018: ask for the smallest physical ingredient actually available.
SPAWN 019: seek the largest plausible bounded consequence.
SPAWN 020: recombine hats and invert assumptions to imagine new possibilities.
**SPAWN 021: record real tests, learn what didn't work, invent safe new recombination moves, and re-rank imagination.**

## New features

- A **Run + observe this hypothesis** button on each imagination idea and counterfactual fork stages a concrete TODO on an existing hat and links an evidence-ledger record to the actual task ID. It does not mark the task done or assert an outcome.
- To report a **worked** experiment, the task must be marked DONE with its own meaningful observation. To report **failed**, it must be BLOCKED with an observation. Mixed results require a recorded done/blocked task. An experiment must include a separate real observation (20+ characters) and a revision/lesson (8+ characters). These are **self-reports**, not independently verified evidence.
- A worked report increases the modest ranking weight of that transformation lens; a failed test reduces it. Contributions are capped and only count while their linked task remains done/blocked with an actual observation. Clicking cards, generating descriptions, or adding an idea has no learning effect.
- **Invent a new imagination move** lets the operator author a declarative rule with typed role slots, such as **{{A}}** and **{{B}}**, an observable first test, a falsification condition, a first material category, and optional provenance to a recorded worked trial. These are plain text with validated placeholders—never executable code.
- A one-hat rule can recombine with every actual operation; two- and three-hat rules produce new cross-hat hypotheses. Nothing creates fictional partners or transfers physical resources. New rules are explicitly operator-reviewed but still experimental, even if one earlier user-reported trial worked.
- Pausing a rule stops future generation without deleting the actual workboard outcomes. Evidence source support is withdrawn when its task no longer shows a completed observed trial.
- A private SPAWN state backup now includes the bounded trial-and-rule ledger. The previous private backup schema remains readable and imports with an empty learning ledger. Shareable method cartridges do not include test observations or learning rules.

## Try it

1. Open Lantern_021_Learning_Loom.html locally. Seed the organizer, grower and artist roles, or create your own.
2. Go to the Imagination Loom; select an unusual cross-hat proposition and choose **Run + observe this hypothesis**.
3. Actually try the smallest physical or digital step. Mark the linked task **Done** (if accomplished) or **Blocked** (if not) and record what happened.
4. In the **Learning Loom**, select **Test worked**, **Test failed**, or **Partial/mixed**, include an actual observation and a next revision. This is your own report, not externally verified.
5. If a useful outcome occurred, use **Derive a possible new move**. Review and edit the proposed slot-based transformation before choosing **Review and add my experimental move**.
6. Return to **Weave possible worlds**. New hypotheses now include recombinations generated by your added rule. Their origins label whether they have a source trial or remain wholly untested. Pausing the rule removes its ideas from the next recombination.
7. Repeat a test under another hat. A single result is not general proof; the useful change would be seeing a new method reproduce successfully with independent real evidence.

## Reality boundaries

- The engine remains a deterministic, static offline application. It does not connect an LLM, train a model, scan websites, touch Supabase, send invitations, book a venue, spend money, or operate external equipment.
- The so-called learning is **bounded evidence-conditioned score adjustment and declarative rule authoring**, not autonomous learning or modifying running JavaScript. Human review is mandatory to add a rule. A rule is a hypothetical *method to test*, not an executable permission.
- A status recorded by the operator is not independently audited. Safety of food, equipment and venues, consent, suitability of materials, lawful access and availability are separate reality checks.
- A failed test remains a valuable signal. Its original task is not silently rewritten; a revised method creates a new hypothesis and task.
- Up to 80 linked trials and 18 custom rules are stored privately; user-entered text is bounded. LocalStorage may be lost, so download private backups for important work. Reusing a public preview on a third-party domain could expose private entries to that operator; use a trusted local copy for private information.

## Status, tests and missing proof

Source lives on draft PR #170 stacked atop SPAWN 020 #169. Test entry: node --test experiments/lantern-commons-014/test_learning_021.mjs . The project CI runs the inherited tests too.

We have **software tests** for evidence gates, user-reviewed rule creation, outcome-based ranking, cancellation/downgrade of reported successes, cross-hat combination, malformed-data rejection, and no invented physical outcomes. We do **not** yet have evidence of real-world improvement in idea quality, genuine economic circulation, public deployment or reproducible community adoption.
